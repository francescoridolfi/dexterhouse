# Team sizing

Propose a specialist only if all hold:
1. At least one task needs knowledge the generic developer or tester lacks (a frontend framework, mobile, data pipelines, security review, infrastructure as code).
2. The specialist's role is narrower than the built-in one and its tools are not wider.
3. The evidence is concrete: verified, rating >= 4, a meaningful number of installs, compatible with this core.

Do not propose: for "safety", for tasks already simple, for a second generic developer, process packages, anything with a high-risk permission.
Zero proposals is a valid answer; say why in the summary.
